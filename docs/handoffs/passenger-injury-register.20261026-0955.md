## 2. 数据源定义
### 2.1 原型事实（静态源码核对）
| 字段 | 类型 / 约束 | 来源与说明 |
|---|---|---|
| personCount / persons | 人数 1–50；人员数组 | 四步向导；人员行含姓名、性别、年龄、受伤部位；年龄控件 0–120，受伤部位文本最多 30 字 |
| occurTime | datetime | 必填标记；格式 YYYY-MM-DD HH:mm:ss |
| location | 车站选择 | 按线路展开，线路节点不可选 |
| position | string | 必填标记；自定义具体位置 |
| weather | enum | 必填标记；取 ksWeatherOptions，正式工单须逐项提取 |
| center / line | string | 选择车站自动带出，界面禁用编辑 |
| incident / cause | text | 必填标记 |
| attachments | 文件列表 | 原型有附件交互，正式工单须补类型、大小、存储与删除约定 |
| status | 审批状态 | 通过写“已审批”，退回写“待审批”；台账过滤“已审批” |

必填标记不等于已执行校验，正式工单须核对提交处理函数。组织树是“运营一至四中心”，不得直接套用 README 的历史字典摘要。

### 2.2 现有工程实现（不是目标需求）
`src/stores/passengerInjury.js` 用 reactive 单例保存 injuryRecords，刷新丢失；approvedInjuryRecords 按 approvalStatus === '审批通过' 过滤。genRecordNo 使用当前年份和所有记录尾号的最大值加一，未按年份过滤，不能描述成“当年最大序号”。目标编号规则待确认。

### 2.3 生命周期与接口
原型通过后进入台账，退回恢复待审批。原型审批意见有输入框，但 handleKsApprove 未保存意见；src 将 approveComment 写入记录。生产持久化、权限与接口契约均待确认，本样例不指定接口地址。

## 3. 界面要点
- 页面含组织树、统计、关键字/线路/审批状态筛选、表格和分页。
- 登记弹窗为基本信息 → 人员及伤情 → 经过与分析 → 汇总信息四步向导，支持多人。
- 车站联动中心与线路；发生位置和人员受伤部位允许文本输入。
- 审批弹窗包含可选意见，通过/退回操作；台账关联 ksTableData。
- 表格完整列顺序、所有按钮及权限、向导提交校验、附件限制仍待逐项提取，不作为已完成需求。
